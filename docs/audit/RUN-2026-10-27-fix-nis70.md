## 2. The change

**The rule.** Taxable pay = gross − personal allowance − 70% of the employee NIS contribution. Source: IRD form TD1
2023, line 4(b) "N.I.S (70% of Employees Contribution)".

**Where the engine computes taxable pay or PAYE.** One place: `computeNetPay` in `core/src/household-budget.ts`
(`nisDeductible = nis * 12 * core:ff.tax.nisDeductibleShare`). Every other module reads net pay from it. Searched
`core/src` for `paye`, `taxable`, `nis` (case-insensitive): no second computation.

**The parameter.** `core:ff.tax.nisDeductibleShare` in `core/src/parameters/fact-finder-2026-10.ts` was already a row
(value 1, status `assumed`, source the prototype, with a 100%-vs-70% caveat). It is now value **0.7**, status
`verified`, source "IRD form TD1 2023, line 4(b) …", `asOf` **2026-10-27**. The caveat is removed: the conflict it
described is settled. No constant was added to code.

**No-hard-coded-parameter test.** `core/test/purity.test.ts` now forbids `0.7` and `0.70` in executable engine code
(sabotage in §6).

**`feat/domain-core`.** Checked: its `core/src` computes no PAYE, and its `parameters/tt-parameters.js` `incomeTax()`
already uses the root `income_tax.nis_deductible_portion` (0.70). The 100% rule does not live there, so there is no
domain-core commit and no merge into `feat/fact-finder-engine`.

**Version id.** `ASSUMPTION_SET_ID`: old **`ff-2026-10-27`**, new **`ff-2026-10-27-nis70`**. Goldens test, dist test and
the portal record the new id.

**Rounding.** Unchanged. Goldens round with `Math.round`; the page formats money with the engine's `money()`, which
rounds to whole dollars. So the page shows the family ceiling as **$711** (710.8425) and the young single's as
**$374** (374.1425). The brief's "$710.84" and "$374.14" are the unrounded values.
